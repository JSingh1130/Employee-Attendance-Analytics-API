# REVIEW.md

Findings in the starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` | Always returned `ok`, even when MongoDB was unavailable. | Stop MongoDB and call `GET /health`; the starter still returned 200. | Ping MongoDB and return 503 on a PyMongo error. |
| 2 | Startup / indexes | No application indexes existed, so duplicate employee and attendance records were not database-enforced and list queries had no supporting indexes. | Start with an unindexed database; concurrent duplicate writes could both pass a pre-check and attendance listing could scan the collection. | Create idempotent unique natural-key indexes plus indexes for employee department and attendance filters/sort. |
| 3 | `EmployeeIn` | Accepted malformed employee codes, emails, dates, invalid shifts, and identical shift bounds. | Try `emp_code="x"`, an invalid date, or identical shifts; requests passed model validation. | Enforce contract field constraints, validate real calendar dates, and reject equal shift times. |
| 4 | `create_employee` | Check-then-insert was race-prone; simultaneous creates could both pass `find_one`. | Send parallel creates with the same `emp_code`; without a unique index both could return 201. | Make the unique index authoritative and translate `DuplicateKeyError` to 409. |
| 5 | `create_employee` / response | `created_at` was a naive local datetime and serialized as a string, not epoch milliseconds. | Inspect a created response and stored BSON instant under a non-UTC host timezone. | Store UTC and serialize `created_at` as integer epoch milliseconds. |
| 6 | `list_employees` offset | Used `page * page_size`, skipping the first page's records. | With page 1 and page size 20, the query began at item 20 instead of item 0. | Use `(page - 1) * page_size`. |
| 7 | `list_employees` total | Counted the entire collection rather than the filtered query. | Filter by a department and compare `total` with the number of matching employees. | Pass the same filter to `count_documents`. |
| 8 | `list_employees` ordering | Did not sort by `emp_code`, so page order was not contractual or deterministic. | Repeatedly list employees and observe order differing from ascending employee code. | Sort in MongoDB by `emp_code` ascending. |
| 9 | Employee/attendance list parameters | Pagination had no lower/upper validation; invalid page values could produce incorrect slices and page sizes could exceed the contract limit. | Request page 0, negative values, or page size 101. | Validate `page >= 1` and `1 <= page_size <= 100`. |
| 10 | `punch_in` employee lookup | Dereferenced `emp` without checking for a missing employee, causing a 500. | Punch in using an unknown employee code. | Return 404 before reading shift fields. |
| 11 | `PunchInIn` | Timestamp accepted coercible values and lacked the documented epoch-millisecond range; status accepted arbitrary strings. | Send a float/string/seconds timestamp or `status="LEAVE"`. | Require a strict integer in the permitted range and restrict status to presence statuses. |
| 12 | `punch_in` timestamp/date | Used host-local `fromtimestamp`, host-local current time, retained fractional seconds, and used the local date directly; this violated UTC/IST conversion, truncation, and overnight attendance-date rules. | Change host timezone; test an IST-midnight boundary or a 22:00–06:00 shift; send milliseconds with a fractional second. | Normalize instants to UTC, truncate to seconds, derive the IST date, and assign pre-shift-end overnight punches to the prior shift date. |
| 13 | `compute_late_minutes` | Floored elapsed minutes before applying the 10-minute threshold, so 09:40:01 for a 09:30 shift incorrectly became 0 late minutes. | Test the contract boundary values 09:40:00 and 09:40:01. | Compare elapsed seconds to 600 first, then floor whole minutes from shift start. |
| 14 | `compute_work_hours` | Python `round` uses ties-to-even and float arithmetic, not the required decimal half-up rule. | Use a duration whose hours are exactly halfway between hundredths. | Calculate from truncated seconds with `Decimal` and `ROUND_HALF_UP`. |
| 15 | `compute_overtime` | Assumed shift end was on the attendance date and counted any positive overtime, ignoring the 30-minute minimum. | Test an overnight shift and punch-outs 29:59 and 30:00 after shift end. | Advance overnight shift end to the next day and count only when elapsed time is at least 30 minutes. |
| 16 | `punch_in` duplicate handling | A read-before-insert duplicate check was not atomic, so simultaneous punches could create two records. | Send parallel punch-ins for the same employee/date. | Enforce unique `(emp_code, date)` in MongoDB and map duplicate-key failures to 409. |
| 17 | `list_attendance` query execution | Loaded every matching document, sorted and paginated in Python, which does not scale to 100,000 records. | Inspect behavior with a large collection; memory and latency grow with the full result set. | Count in MongoDB and apply sort, skip, and limit before materializing results. |
| 18 | `list_attendance` ordering | Sorted only by date, not the required `emp_code` ascending tie-breaker. | Create multiple records on one date and inspect their order. | Sort by date descending, then employee code ascending. |
| 19 | `list_attendance` response | Returned an `id` from `_id`, although MongoDB identifiers must not appear in the API; BSON instants also leaked as ISO strings rather than epoch milliseconds. | Inspect a list response containing a punch time. | Exclude `_id` and serialize the exact attendance fields and nested history instants. |
| 20 | `list_attendance` validation | Accepted malformed dates, reversed ranges, and unknown status values. | Send an impossible date, `date_from > date_to`, or invalid status. | Parse dates as calendar dates, reject reversed ranges, and validate status against the contract enum. |

Looked at and decided these were not defects: `load_dotenv()` does not override real environment variables by default, so injected environment values retain priority; the remaining endpoints were explicitly marked TODO for Part B rather than implemented starter endpoints.
